# Student Analytics & Automated Report Generator

A single Streamlit + Plotly analytics platform that merges two reference projects into one:

| Reference project | What was taken from it | Where it lives here |
|---|---|---|
| [`Automated-Student-Report-Generator-with-Data-Visualization`](https://github.com/akramlodi/Automated-Student-Report-Generator-with-Data-Visualization) | Customizable exam weightages → weighted final grade, per-student PDF report cards, bar charts comparing the student to the class average | `core/grading.py`, `core/report_pdf.py`, the **Report Cards** page |
| [`grade-tracking-Canvas-API`](https://github.com/jlouisbru/grade-tracking-Canvas-API) | Fetching students / assignments / the full gradebook from an external LMS instead of typing marks in, and pushing grades back | `integrations/canvas_api.py`, `integrations/google_forms.py`, the **Integrations** page |

Everything runs locally on generated CSV data — **no API key is required to use any feature.**

## Quick start

```powershell
cd "school ai"
pip install -r requirements.txt
.\start_analytics_dashboard.ps1                   # http://localhost:8502
```

The committed `.parquet` data means it runs straight away. To rebuild the dataset (and the
CSV / Excel copies) from scratch:

```powershell
python -m student_analytics.generate_dataset
```

The original School AI app still runs independently on port 8501 (`.\start_frontend.ps1`).

## The dataset (`student_analytics/data/`)

Generated by `generate_dataset.py`. **1,800 students** across **grades 8, 9 and 10**, 4 campuses,
4 sections per grade per campus (48 sections of ~37 students), 8 subjects, 4 exams,
10 months of attendance — **~108,000 rows** in total, ~12 MB as CSV.

| File | Rows | One row = |
|---|---:|---|
| `students.csv` | 1,800 | a student (demographics, guardian, lifestyle attributes) |
| `marks.csv` | 57,600 | student × subject × exam |
| `master_student_subject.csv` | 14,400 | student × subject, with the weighted grade, rank, percentile and class comparison already computed |
| `student_summary.csv` | 1,800 | student, fully analysed: overall %, GPA, letter grade, 3 kinds of rank, attendance, risk score, performance band |
| `attendance_monthly.csv` | 18,000 | student × month (present / late / leave / absent days) |
| `assignments.csv` | 14,400 | student × subject homework record (assigned, submitted, on time, average score) |
| `survey_responses.csv` | ~1,570 | a simulated Google Form response (study hours, sleep, screen time, motivation, stress…) |
| `classes.csv` / `subjects.csv` / `teachers.csv` | 48 / 384 / 96 | reference tables |
| `master_student_analytics.xlsx` | — | the same data as a multi-sheet Excel workbook |

### What is committed to git

Only the **`.parquet` copies (~1.4 MB total)** are committed — they are ~18× smaller than
the CSVs and load faster, so a fresh clone or a cloud deploy comes up with data immediately
and needs no generation step. The CSVs and the Excel workbook are gitignored build outputs;
regenerate them any time with `python -m student_analytics.generate_dataset`.

`core/loader.py` prefers `.parquet` and falls back to `.csv`, and the dashboard
auto-generates the dataset on first run if neither is present.

### Why the data behaves realistically

The rows are not random noise. Each student gets a **hidden latent profile** — academic
ability, diligence, term-over-term momentum and a per-subject aptitude — and every visible
column is derived from it plus noise:

- attendance and assignment submission are driven by *diligence*, so the
  attendance ↔ marks correlation is real (r ≈ 0.35–0.5), not accidental;
- lifestyle answers (study hours, sleep, screen time, motivation, parent education) are
  correlated with the latent profile, so the **drivers-of-performance** analysis finds
  genuine signal to rank;
- ~7% of students are deliberate strong improvers and ~6% decliners, so **momentum**
  analysis has something to find;
- exam paper difficulty is balanced between the first and last exam, so a student's
  Unit Test 1 → Final Exam delta measures *their* trajectory rather than a systematic drift.

Regenerate at any size: `python -m student_analytics.generate_dataset --students 4000 --seed 7`
(`--no-excel` skips the slow workbook step; `--no-parquet` skips the compressed copies.)

## Deploying to Streamlit Community Cloud

The repo is already deployment-ready:

| Setting | Value |
|---|---|
| Main file path | `student_analytics/dashboard/Home.py` |
| Python version | 3.11+ |
| Dependencies | `requirements.txt` (repo root, auto-detected) |
| Theme / server config | `.streamlit/config.toml` |
| Data | committed `.parquet` files — no generation needed at boot |

Resident data is ~55 MB, comfortably inside the free tier's ~1 GB limit. No secrets or API
keys are required for the app to run; add the Canvas / Google values from `API_SETUP.md` as
app secrets only if you want the live connectors enabled.

## How grading works

Configured at the top of `config.py`, and adjustable live in the dashboard's weightage
playground:

```
weighted_exam_pct  = Σ(exam % × weight) / Σ(weights)
                     Unit Test 1 15% · Mid Term 25% · Unit Test 2 15% · Final Exam 45%

final_subject_score = 80% × weighted_exam_pct + 20% × assignment_component
                      (assignment_component = average assignment score, scaled by how many
                       were actually submitted — missing work costs marks)

letter grade        A+ ≥91 · A ≥81 · B+ ≥71 · B ≥61 · C+ ≥51 · C ≥41 · D ≥33 · E below
pass mark           33%
```

**Performance bands** come from the student's percentile *within their own grade*:
Topper (≥90th), Above Average (≥60th), Average (>25th), Needs Improvement (≤25th),
overridden to **At Risk** when the composite risk score is high and the score is below 50%.

**Composite risk score (0–100)** blends four signals so that a student who is currently
weak is distinguished from one who is actively falling:

| Signal | Weight |
|---|---:|
| Low overall score | 40% |
| Low attendance | 25% |
| Negative trend (UT1 → Final) | 20% |
| Low assignment submission | 15% |

→ Low / Moderate / High / Critical bands, each with a plain-English `risk_reasons` string.

## Module layout

```
student_analytics/
├── config.py                  paths, dataset shape, weightages, grade bands, thresholds, credentials
├── generate_dataset.py        the latent-profile data generator (CLI)
├── smoke_test.py              runs every analytics function, chart and PDF path
├── dashboard_test.py          headless render test for all 9 dashboard pages
├── API_SETUP.md               step-by-step credential guide with signup links
├── core/
│   ├── loader.py              cached dataset loading + the Dataset object
│   ├── grading.py             weighted grades, letter bands, live re-scoring
│   ├── analytics.py           scoping, KPIs, ranks, toppers, at-risk, subjects, correlations, intervention plans
│   ├── insights.py            rule-based narrative generation (+ optional Ollama polish)
│   ├── charts.py              30 Plotly figure builders
│   └── report_pdf.py          reportlab + matplotlib report cards and class reports
├── integrations/
│   ├── canvas_api.py          Canvas LMS: courses, users, assignments, gradebook, grade upload
│   └── google_forms.py        Google Sheets/Forms: published CSV or service account, header auto-mapping
├── dashboard/
│   ├── shared.py              CSS, cached loading, sidebar filters, KPI cards, table styling
│   ├── Home.py                Class Command Center
│   └── pages/1..8             the eight drill-down pages
├── data/                      generated CSVs + the Excel workbook
└── output/reports/            generated PDF report cards
```
